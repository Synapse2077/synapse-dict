# 📋 BACKLOG —— 全仓唯一的顶层账本

> 2026-09-20 建。用户原话：「**你只有记在顶层，你才知道所有语言留下来的所有问题**。」

## 为什么建这个文件

在它之前，**这个仓库没有顶层账本**，六门各自发明了一种记账形状：

| 文档 | 它的账记在哪 |
|---|---|
| `DE_PLAN` | `# 📋 de 收尾单` ＋ `## 二、🟡 可发布，记账` |
| `EN_PLAN` | `### 16.7 顺带记账` |
| `FR_PLAN` | 按阶段散落的若干个「记账」小节 |
| `IT_PLAN` | `#### ⚠️ 顺带发现、已记账未决` ＋ `# 四、it 收尾单` |
| `JA_PLAN` | `## 六、📋 欠账` ＋ `## 收尾单的交接` |
| `PT_PLAN` | `# 📋 pt 收尾单` ＋ `收尾单 C1–C59` |
| `PITFALLS` / `PLAYBOOK` / `FRAMEWORK` | **没有账本章节** |

于是**跨门的账只能寄存在「发现它的那一门」**，而做别门的人永远看不到它。
`JA_PLAN` 的 24 行欠账里，**12 行（50%）牵涉别门**。三个已经发生的后果：

- **en 的账躺在 `JA_PLAN` 里**（本文件 B1），从 ja 开工起没人看得到。
- **`split_colloc` 那条写着「日语开工前必须先改」**（B2），而这个前提早就失效
  （ja 压根没有搭配层）—— **没有人会去复查一个躺在别人账本里的前提。**
- 跨门的「收词之后哪些层要重跑」被写成**两行、结论相反**地躺在 ja 表里
  （2026-09-20 才发现并合并，顺带补了 P8 闸）。

🔴 **而最能说明问题的是：「这个仓库总共欠什么」这个问题，此刻没有任何人能回答，包括我。**
我试过用状态符号扫六份文档，得到 137 行「开着的」—— 那个数**不算数**：
🔴 在这些文档里**绝大多数是强调不是状态**（`🔴 ECDICT 的人工中文换身份`、
`🔴 阶段 1.5 实测这一段不花钱`）。`test_plan_ledger.py` 的 P7 注释里早记过这一课：
**同一个符号在六张计划表里含义不同，按符号判会在 37 行上误报。**
⇒ 信息不在一个可机读的形状里，这本身就是本文件要解决的问题。

## 规矩

1. **跨门的账、别门的账，一律记在这里**，不许寄存在某一门的计划表里。
   各门的计划表只记**它自己的**账。
2. 每条必须写清 **影响哪几门** 和 **什么算结清** —— 否则它就是一条永久前提
   （`[[record-the-negative-decision]]`：否定结论必须写什么会推翻它）。
3. 🔴 **本文件必须被闸盯着，否则它会变成一个更大的垃圾场。**
   per-language 的账本今天还活着，唯一原因是 `test_plan_ledger.py` 的 P1–P8 逐行读它。
   一个没有闸的顶层文档，下场就是「收词之后哪些层要重跑，没有清单」那条 ——
   **写下来了，然后烂在那儿**（`[[lesson-must-become-mechanism]]`）。
   ⇒ 已有 **P9**（各门的账的闸）：**这一门的欠账表里不许出现「不是 X 的账」那种行**，
     有就当场红，逼它搬到本文件来。本文件自己的闸尚缺，见 B5。
