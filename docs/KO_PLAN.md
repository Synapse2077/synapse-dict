### 🔴🔴 结论一：中文版不是补料，它是最大的一份

前七门的惯例是「英文版 per-language 切片当骨架，别的版本补料」。韩语上这条**整个反过来**：

```
中文版两片有释义词头合计   238,507     ← 是 ja（83,234）的 2.9 倍
英文版有释义词头            51,163
韩文版有释义词头            68,222

中文简体片 195,332 个词头里
  ├ 在 英文版∪韩文版 里的    38,366  (19.6%)
  └ 🔴 别处都没有的         156,966  (80.4%)   ← 99.99% 是纯谚文，抽样全是真词
       样本：가다가다(偶尔) 가득차다(装满) 간절히(恳切地) 갈라놓다(分开)
```

⚠️ **但这 15.7 万只有释义**：pos 99.5% 是 `unknown`、IPA 701 条、forms 718 条、词源 0。
全收会造出十几万个「有中文释义、没词性没读音没活用」的半成品 —— 就是 pt 栽的那个形状
（**355,605 个词形＝搜得到、点进去空白页**）。⇒ **这是 §四待定的第一条，不许顺手全收。**

| ko 韩文版 | 30,982 | 31.6% |

`past` 107,444／`non-past` 86,848／`indicative` 80,995／`interrogative` 80,912 ——
**敬语阶 × 时制 × 语气三维都在英文版里**。
🔴 照 ja 的结论走（「活用只有本语种版才有」）会把最全的那份当成最差的那份。

## 二、已定的判据（每条都回源核过）

1. **罗马字不许进词形**。英文版 59,148 个、韩文版 34,396 个 `form` 带
   `romanization`/`transliteration` tag（`gyoga`、`bakkuda`）。判据用 **tag**，
   **不用「长得像不像拉丁字母」**（`[[criteria-from-meaning-not-form]]`）。
2. **中文版的 `examples` 里混着关系数据**，抽取前必须过滤：`가을` 的 examples 有
   `近义词：추`／`派生詞：늦가을，올가을…`／`季节：봄 - 여름 - 가을 - 겨울`。
   它们是**关系层的料**，不是例句。⚠️ 顺序不能反：先过滤再送模型，否则会把
   「近义词：추」当例句翻出来（`PLAYBOOK` 5.5 同一个坑）。
3. **释义只保留三语：中文 + 英文 + 韩语**。⇒ 日文版那 29,671 条日语释义**不进库**，
   它只用来给 IPA 交叉背书。
4. **「是不是中文」只许用 `ko/dbtool.is_chinese_text(s, src)`**，`has_han` 这个名字
   在 `ko/dbtool.py` 里**故意不存在**：韩语的汉字表记条目（`符號`、`孫女`）是纯汉字，
   `has_han` 在它们上恒真。纯汉字串拿不到 `src` 时**抛异常，不猜**。
5. **IPA 归信人工源**，只有跨版权威源裁决才能推翻（`PLAYBOOK` 3.2）。
   ko 有三版 IPA（韩文 71,016／英文 40,123／日文 15,431）⇒ 背书材料充足。
6. **不做自动判重**（`PLAYBOOK` 5.6：es 的 186 条判重里 12.4% 是义项错配）。
7. 🔴 **读音层不许读 `sounds[].other` 字段** —— 它在韩文版里装的**全是日语**。
   实测：全切片 `other` 字段 52 条，**100% 是假名**（`無料`→`むりょー` 带东京式声调
   Heiban/Atamadaka）。那是韩语汉字词顺带标注的日语读音。
   ⭐ 判据按**字段**排除比按 tag 排除干净：韩语读音的家是 `ipa` / `hangeul` / `roman`
   三个字段（实测 337,982 / 105,743 / 102,382 条各自字形纯净），`other` 一条韩语都没有。
   ⚠️ 对照 ja：日语版的 `other` 装的是声调 —— **同一个字段名在不同版本里装不同东西**，
   换版本必须重新量。
8. **谚文归一 = NFC，入库侧零转换、检索侧必须做**。实测两版词头 **100% 已是 NFC**
   （分解形 0 条）⇒ 入库不转。但 macOS/iOS 的输入法与剪贴板会产出 NFD 谚文
   （`가` 拆成 ᄀ+ᅡ），长得一样、字节不同、`=` 匹配不上 ⇒ **查询串必须归一**。
   🔴 「源头干净」和「不需要归一」是两件事。

### 阶段 0 落下的六处结构决定（判据全文在 `ko/pipeline/build_v3_schema.py` 文件头）

| # | 决定 | 实测判据 |
|---|---|---|
| ① | **四套罗马字放 `entry`**，不放 `pronunciation` | 记录内同套罗马字有 ≥2 个值的只有 **0.08%**（MR 5 / Yale 55），而 IPA 多值的有 **22.6%**（15,928 条）⇒ 罗马字是词条属性、IPA 是读音属性 |
| ② | **`entry.hanja` 单值列**，异体字进关系层 | 一条记录内 1 个 hanja 的 18,453（99.4%）／2–3 个的 100 条，全是异体字或数字写法（奇跡/奇蹟/奇迹、10月/十月）<br>🔴 **但绝不能放 `dict`**：1,944 个词形对应 ≥2 个不同汉字（`양` → 壤/兩/良/陽/孃/洋/量/羊），分属不同 entry |
| ③ | **`pronunciation.hangeul_phonetic`** —— 韩语独有的一层 | 102,389 条发音形谚文（`읽다`→`익따`），与 IPA 大多一一对应。⭐ 它还是 §四.1-c 的**真值标尺** |
| ④ | **不建 `pitch_mark` / `pitch_pos`**（ja 有） | 韩文版 IPA 的 tags 值域**只有 SK-Standard / Seoul 两个值**，一个声调标记都没有。推翻条件：收庆尚道/咸镜道方言（那些**有**音高重音）|
| ⑤ | **不建 `entry.vclass`**（活用类 ㅂ/ㄷ/르 불규칙） | 英文版 **0 条**；韩文版只在 categories 里给 **452 条**＝它自己用言的 4.3%，源头本身不全。而我们**直接有 359,583 个变形词形** —— 需要的东西已在手上<br>⚠️ 第一轮我差点用**行级预筛**得出这个结论（`PITFALLS` B 组禁止），数是全量重扫的 |
| ⑥ | **`etymology` 从第一天就建** | ja 做完九个阶段、打完完结标记才发现这张表整个不存在（46,196 个条目带词源、一条没抽，而阶段表全 ✅）。根因是**阶段表对没列进去的层结构性失明** |
| ⑦ | **不建 `pronunciation_entry`** | 需要「一个读音属于部分而非全部 entry」的词形：英文版 **429 个（0.75%）**、韩文版 54 个。而 `UNIQUE(word_id, entry_id, ipa, notation)` 主键**含 `entry_id`** ⇒ 复制成两三行就装下，冗余约 1,000 行<br>（对照：es 实测 14 个不建／it 建了 282,060 行 —— **各门自己量，不看别门有没有**）<br>🔴 推翻条件：复制出来的读音行超过 `pronunciation` 总行数的 5% |

## 四、待定（列在这儿是为了不假装已经定了）

### 4.1 ✅ **已定（2026-09-20，用户拍板）：中文版那 156,966 个词头全收，并且出版**

词头从 5.7 万 → **21 万量级**。我给的建议是「先收进证据层不出版」，用户选了**全收并出版**
（方针①「词全」压过「半成品词条」的顾虑）。

🔴🔴 **这个决定会直接触发 pt 栽过的那个形状**，所以它不是一句话，它带着四条必办事项。
记在这儿不是留个印象，是因为**每一条都要有东西替它站岗**：

| # | 必办 | 为什么 | 什么时候做 |
|---|---|---|---|
| **a** | 收词落库后**立刻**查一次「既无可见义项、又不在 `inflection` 里的词形有多少」 | 这个数就是"点进去是空白页"的词形数。pt 是做到阶段 5 之前分层量数才撞见的，中间隔了整整两个阶段（`PLAYBOOK` 四）| 阶段 4 当天，不是阶段 5 |
| **b** | 收词必须声明 `invalidates=[...]`，**且这一次名单一定非空** | ko 的收词是七门里最大的一次（+15.7 万词头）。已知与词元数挂钩的层：变形层 / 读音层 / 释义中文覆盖 / 频次层 / 验收闸。B3 那张清单**至今不存在** | 阶段 4 |
| **c** | 这 15.7 万的**读音**要靠谚文→IPA 规则生成来补，不能空着 | 谚文是**音素文字**，转写规则性远高于拉丁语言的 G2P；但**音变（连音/同化/紧音化）才是难点**，`읽다`→`익따` 那一层韩文版给了 10 万条真值可以拿来验。⚠️ **先验后用**：`PLAYBOOK` 3.3「别用 G2P 重算」的教训是在拉丁语言上得的，韩语要不要走这条路，判据是**拿韩文版的发音形谚文当标尺实测准确率**，不是类比 | 阶段 3 之后、阶段 4 收词之后**重跑一次** |
| **d** | 词性：这批 `pos` 全是 `unknown`，**不许瞎填** | 错比缺更伤权威。韩语的词尾高度规则（`-다` 结尾是用言、`-하다` 是动词/形容词），但**规则能覆盖多少要实测**，覆盖不到的就留 `unknown`，不猜 | 阶段 5 |

🔴 **什么会推翻这个决定**：阶段 4a 那个数（空白页词形数）如果在补完 c、d 之后
**仍然超过总词形的 10%**，就回来重新讨论「出版」这一半 ——
收进库是可逆的，出版给读者看是要负责的。

### 4.2 ✅ **已定（2026-09-20，用户拍板）：四套罗马字全存，页面只显示 RR**

revised（RR，韩国 2000 年起的官方国标）/ RR-transliteration / McCune-Reischauer / Yale
**四列全部入库**，展示层**只显示 RR**。

🔴 **「只显示 RR」是一个决定，决定必须有东西替它站岗** —— 否则它会在某次展示层改动里
悄悄失效，而所有数据闸全绿。照搬 ja 给 `core_level` 做的那道闸（X3）：

> **回归闸不查数据、查源码**：展示层源码里不许出现另外三个列名。ja 的 X3 用变异 M42 验过。

⇒ 阶段 8 建回归闸时，这条是**必列项**；在那之前，阶段 0 定 schema 时就要把四个列名
定成**能被源码扫描认出来的样子**（别叫 `roman1`/`roman2`，要叫
`roman_rr` / `roman_rr_translit` / `roman_mr` / `roman_yale`）。

⚠️ 代价说明白：多三列要进 `TRACK`、进闸、进备份。这是用户知情选择的
——「数据不丢」压过「三列的维护成本」。

### 4.3 🔴🔴 **这条结论当天就被推翻了 —— 而推翻它的不是新证据，是我量错了对象**

**原结论**：「`한자` 切片当作 `sense_src` 的一个来源收，不开独立层」，
判据是「`한자` 切片只能净增 619 个字头」。

**那句话是真的，但它回答的不是这个问题。**
韩语汉字音的数据**根本不在 `한자` 切片里** —— 在**英文版的 `pos=syllable` 条目**里：
**8,640 条义项、343 个音节、6,409 个不同汉字**（`사` 171 条／`정` 154／`주` 131）。
⇒ 阶段 1 已建 `hanja_reading` 表，**8,594 行**。

🔴 **这是 `[[criterion-true-half-vouches-for-false-half]]` 的又一次**：
判据的前半句带着数字、是真的，于是给后半句那步**没验过的推理**背了书。
⚠️ 而**逮到它的不是闸，是抽样反验** —— 建义项层时看见 `주` 有 53 条"义项"、
内容只是一个汉字。`PLAYBOOK`：**不变量证明不了"改对了内容"，只有人眼看得出来。**

⇒ 教训不写成一句话，写成规矩：**「某某源里没有」不能推出「这个层不需要」**，
  因为那个层的数据可能在别的源里。**否定一个层之前，要把每一份源都问一遍。**

### 4.3-旧 ~~`한자` 切片当作 `sense_src` 的一个来源收，不开独立层~~（已被上面推翻）

韩文版把「汉字」单列成一个**语种**（`lang: 한자`，`lang_code: unknown`），
释义是韩语写的（`言` → `말씀, 말`）。

**量出来的数**：
```
英文版里纯汉字词头        22,056（其中 pos=character 的条目 9,939）
`한자` 切片                3,917 个字
  ├ 与英文版交集           3,298（84.2%）
  └ 能净增                   619
```
⇒ **净增只有 619 个字头**，而它能给的是「这个汉字在韩语里的字义」——
那正是 `sense_src` / `sense_gloss` 装的东西，**不需要新表**。
⚠️ **与 ja 的 `kanji_reading` 不是一回事**：那是**读音**表（呉音/漢音/訓…一组分类读音，
单值列装不下所以必须开表），这是**字义**表（一条条释义，现成的表就能装）。
🔴 「日语有 `kanji_reading` 所以韩语也该有」这个推理**在结构上就是错的**，
不是"量小所以不做"。

🔴 **什么会推翻它**：若发现韩语汉字也有「一组带分类的读音」（如朝鲜汉字音的
舊音/俗音之别）且源头成规模地给了 —— 那时才需要一张 `hanja_reading` 表。
本轮实测：`한자` 切片 4,023 行里带 `sounds` 的只有 72 条（IPA 40 / 音频 32），**没有分类读音**。

#### 标尺为什么能用 —— 这一条必须先答

标尺 ＝ 韩文版的 65,926 行发音形谚文。最容易犯的错是默认它有代表性。
实测 **发音形 == 拼写形的占 54.8%** ⇒ 源头是**无条件标注**的，不是"只在读音≠拼写时才标"。
⚠️ 另一半偏置**无法从标尺内部证伪**：标尺是韩文版收的词（多为词元），
而应用对象含大量中文版独有词。可观测的代理是「危险边界占比」：
**标尺 64.5% vs 目标 74.3%** ⇒ **目标集更难，98.73% 是上界不是估计值**。

#### 🔴 B 级那张 IPA 表是**量出来的，不是凭语音学知识写的**

凭知识写的第一版 B 级只有 **69.4%**，错的全是记法约定：`ㅉ` 写 `t͡ɕ͈` 不是 `t͈͡ɕ͈`、
`ㅛ` 是 `jo` 而单独的 `ㅗ` 是 `o̞`、`ㅚ` 是 `ø̞`、`ㄴ` **只在 j 介音前**腭化而纯 ㅣ 前不腭化。
回标尺逐条对差异聚合后到 **95.4%**，再收窄三处到 99.56%。
⇒ **约定只能从源头量。量不出来的地方不许按"应该是什么"补。**

#### 两家外审的每一条建议，都在标尺上单独量过「修好几个／弄坏几个」

规矩是「不一致时回源核对，**不取多数**」，而这件事的权威源就在手上。
开发半 20,757 个词形，采纳线＝**弄坏 ≤ 修好的 5%**，且弄坏的逐条看过：

是因为**标尺自己不遵守它**：`검다[검따]` 与 `넘다[넘다]` 并存、`다듬다[다듬따]` 与

🔴 **什么会推翻它**：拿到국립국어원 표준국어대사전的 `발음` 字段（真正的权威源）
并确认它站 24항 这边 —— 那时要翻的不只是这条规则，还有**标尺本身的地位**。

#### 🔴 否定结论 ②：**사잇소리与26항整类不补，宁缺**

`여권`→`여꿘`、`눈길`→`눈낄`、`사건`→`사껀` 这一类，两家独立同结论：
