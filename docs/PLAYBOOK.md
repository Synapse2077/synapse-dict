## 零、先认清一件事：顺序错了要返工，而返工最贵

es 花了约三周，其中**至少三分之一是返工**，返工全部来自两类顺序错误：

1. **先做展示、后定结构** —— 08-07 才把「一词一行」改成「一义项一行」，
   此前所有按行号对齐的工作（8 万条 `en_i` 映射、752 万 tokens）全部作废重做。
   ⇒ **结构在写第一行业务代码之前定死**，照 `SCHEMA.md` v2，别自己再设计一遍。
2. **先修数据、后建闸** —— 修复写在输出层，后续重建把它们抹掉/绕过（`PITFALLS` E4/G1）。
   ⇒ **闸和修复同时做**，修复要能被重建复现。

🔴 **「完结」是一个要写在计划表里的动作，不是一种感觉**（2026-09-01 加）。
做完最后一个阶段时，在 `docs/<X>_PLAN.md` 里写下一节 `# ✅ <lang> 完结` ——
里面是**当天重新查库量的**成品清单、三道闸的条数与变异数、成本、以及收尾单的交接。
这一行有两个机制在认它：

- **账的闸**：阶段表说完成，交付物就必须存在（`tests/test_plan_ledger.py`）；
- **备份保留策略**：完结之后预算从 `MAX_BACKUP_BYTES` 收到 `DONE_BACKUP_BYTES`
  （`dbtool.prune_backups` 规则④）—— 阶段里程碑的意义是「万一这一步做错了退回来」，
  **阶段全做完、三道闸全绿之后这个意义就没了**，留着的是一条已经走完的楼梯。
  pt 实测 11 个 → 2 个（留「整轮重构之前」和「回滚上一步」），释放 6.9 GB。

⇒ 所以**别顺手打这个标记**：它是有代价的，也正因为有代价才可信。

## 二、骨架层：建库（1 天）

```
build.py            kaikki 英文版 JSONL → sqlite（一词一行的骨架）
enrich.py           **原地补一等本质字段 —— 不重建、不搬运，只长新列**
infl_compose.py     变位/变形语法标签，确定性规则组合
```

**⭐ 最重要的一条经验**：`enrich.py` 的做法是「复制库 + 原地补列」，
不是「重建 + 搬运」。库里一旦含了付费数据（翻译、判决），重建就意味着重花钱。

**判据坑**（`PITFALLS` B 组）：
- 同一个词的每个 pos 是**独立的一行 JSON**，行级预筛会漏；
- 一行里第一个 `"word"` 不一定是词头（可能在 `forms[]` 里），用 `findall`；
- `alt_of` ≠ `form_of` —— 混为一谈会造出「Méjico 的 阳性」这种编造标签（es 踩过，3,890 个）。

## 三、音标（2–3 天，es 在这里花的时间最多）

### 3.1 顺序：先归一，再背书，最后才修

```
apply_ipa_norm.py           约定归一（裸串存储，不带 / /）
apply_edition_confirm.py    用本语种版给库内音标**背书**（不改值，只记「谁也这么写」）
backfill_src.py             给 phonetic / translation / gender 各补一列「这个值是谁给的」
fixes/fix_*.py              只修**回源核对后确认是错的**那几族
```

### 3.2 🔴 修音标的唯一判据：回权威源，不是「看着不像这门语言」

es 上最贵的教训：两家模型独立评审，一致把 coda 浊化（31,890 条）和多词次重音
（7,889 条）判成"最大缺陷"。**回源核对后两条全部推翻** —— 99.9% / 96.8% 与 kaikki
逐字一致，那是 kaikki 的记法约定，不是缺陷。

⇒ **既定策略：IPA 归信人工源。** 只有拿到**跨版权威源裁决**才能推翻它
（`fix_x_gs` 是唯一先例：西语版对那批词写 `ks` 7,311 次、写 `ɡs` **0 次**）。

### 3.3 别用 G2P 重算外来词
`eigenvector` → `eixembeɡˈtoɾ`。字符替换表的**顺序本身就是判据**。

### 3.4 变形层不是风险面
es 实测：58.9 万条 G2P 变形层仅 2.3% 被标出（比 kaikki 原生还低）；
真正可疑的是**无背书的那 2.4 万条**。**别按"哪层大"分配注意力，按"哪层没有背书"分配。**

坑：`PITFALLS` A 组全部、C1（跨语种复用正则先验一遍，fr 版重音符位置约定不同）。

## 四、收词（1 天）

```
ingest_edition.py          本语种版收词：把它有、我们没有的词形收进来
ingest_missing_propers.py  补收被大小写去重吃掉的词头
```

**⭐ 跨版收割是一整类容易被忽略的数据源**：语言版 dump 里有**大量其他语言**的词条
且带音标（法语版 742 万条目里法语只占 210 万）。es 从英文版建库、再从西语版收词，
净增 369,001 行（库 767,293 → 1,136,294，+48%），**音标随词白送 99.96%**。

🔴 **两个必踩的坑**：
- **大小写折叠去重会吃掉专名词头**（`Cefalópodos` 头足纲 vs `cefalópodos` 复数，
  es 丢了 573 个）。必须建新行，并把「精确大小写」加成检索的第一排序键。
- **收词后必须堵住自我背书**：新收的词不能反过来给自己的音标背书。
- 🔴🔴 **收词之后必须重跑变形层 —— 否则新收的变形一条链都没有。**
  pt 2026-08-30 实测：变形层（阶段 2b）建在收词（阶段 3）之前，
  收进来的 35.7 万个词形**从此没人给它们连过线** ⇒
  **355,605 个词形（46.2%）既无义项也无变形链＝搜得到、点进去空白页**。
  ⚠️ 对照组：fr 同一口径只有 1.8%（几乎全是词缀）——
  **不是语言属性，是阶段顺序错**（fr 的变形层是从法语版变位表建的，天然覆盖到新词）。
  🔴🔴 **不是两条路，是四条 —— pt 补链补了四步才把孤儿率压到 1.7%**，
  而每一步都是发现**上一步的判据够不着**才有的。换语种时四条都要走：

      2b  form_of   变形页 → 词元     结构化字段，只有变形自己建了页才有  （英文版）
      2c  forms     词元页 → 变形     词元页的变位表，覆盖全套           （各版变位表）
      2d  form_of   变形页 → 词元     **本语言散文写的**，结构化字段是空的 （本语言版）
      2e  form_of   变形页 → 词元     **别的语言散文写的**（fr 版用法语写） （他版）
      2f  alternative 异体 → 本体     **异体不是屈折，它的家在关系层**     （别人的 forms 表）

  ⭐ **四步的落点**（pt 实测）：355,605 → 64,785 → 21,184 → 16,181 → 13,584 → 12,792。
  🔴 **每一次我都以为"补完了"，每一次都是换一个源、换一种写法就漏。**
  ⇒ 判据别写「读 `form_of`」，写「**这个词形的父词元，源头是用哪几种方式说出来的**」。
  ⚠️ 2d/2e 的判据必须**两个独立信号一致**才收（结构化 `form_of[0].word` ＝ 散文结尾的
  `de <原形>`，pt 实测 99.2% 一致，不一致的 41 条一律跳过）——
  wiktextract 在某些版上会把散文片段直接塞进 `form_of.word`。

  ⭐ **怎么提前发现**：收词落库之后立刻查一次
  「既无可见义项、又不在 `inflection` 里的词形有多少」——
  这个数就是"点进去是空白页"的词形数，它**不该随收词一起涨**。
  pt 是做到阶段 5 之前分层量数才撞见的，中间隔了整整两个阶段。

## 五、义项与释义（一周，最贵的一段）

### 5.1 结构：三层，一次到位

```
sense_src     证据层，永不编辑（原文 + src + src_ref）
sense         出版层，DROP 重建（rank / pos / gender）
sense_gloss   文本层（lang / kind / seq / text / src）
```
🔴 **别把「词形」当成「词条」**：es 的 `dict` 113 万行里 86% 是词形却带着音标和 CEFR。
判据（`pos_title` + `form_of`）源头现成，不用猜。

### 5.2 ⭐ 翻译与对齐**一次调用产出**

让模型在翻译的同时吐出「这条对应英文的第几条」，多吐一个字段**零成本**。
实测成本：**46 tokens/词 + 50 tokens/义项**。es 全量 35,283 义项 / 250 万 tokens / 13 分钟。

⚠️ 但**存的必须是原文文本，不是下标**（`PITFALLS` E5）。这个坑 es 栽了四次。

### 5.3 模板在模型前面

能用确定性规则做的一律不问模型：
```
Grafía obsoleta de X.   → X 的已废拼写
Variante de X.          → X 的变体
Apellido.               → 姓氏
Forma femenina de X.    → X 的阴性形式
```
es 补收的 1,963 条里 75 条走模板 —— 不花钱、比模型稳，且**可以确定性回核**。

### 5.4 释义只保留三语

**中文 + 英文 + 本语言**。实测每个维基版只给「自己语言的词」写真定义，
对外语词只写翻译（pt 版 `casa` 当葡语词有真定义、当西语词只抄回 `casa`）。
de/it/fr/pt 版的释义**从没收进库**，不是"选择不展示"。

### 5.5 payload 四条纪律（每条都是踩出来的）

1. **带该词已有的义项** —— 否则模型会把 `qué onda` 又译一遍「你好吗」并排显示两次；
2. **带上位义 `parent`** —— `teléfono` 的 `mobile phone` 挂在 `telephone` 之下，
   单看会译成孤零零的「手机」；
3. **带词性** —— `A` 的 `bishop` 是国际象棋的「象」不是主教；
4. **明说**：学名/`:*` 残渣/句末标点不要带进中文。

⚠️ 送模型**之前**先跑残渣清理，顺序反了会把 `:*Sinónimos: …` 当释义翻出来。

### 5.6 🔴 判重合并这件事，es 上做失败了

补收义项时让模型顺带判「与已有哪条重复」，186 条判重里 **12.4% 是错配**
（`peón` 的「棋子」并进了「行人」）。这是**义项错配**，比翻错一个词严重得多。

⇒ **下一门语言不要做自动判重。** 多一条义项是「缺」，义项错配是「错」，
而**错比缺更伤权威**。真有重复，留到展示层按原文逐字相同去折叠。

## 六、例句 / 关系 / 发音（2 天）

```
ingest_examples.py    七个语言版全收，去重后单独成表
ingest_audio.py       七个源的真人录音元数据
build_relation_layer.py
gen_tts.py            合成发音兜底
```

- **例句只认 kaikki**，Tatoeba / OPUS 排除。
- **发音走 Wikimedia Commons 真人录音**，语言版 dump 直接带 mp3_url
  （英文版几乎没有，**436 倍差**）。三级兜底：真人 > 工具生成 > 浏览器 TTS。
- **录音可以跨版取并集**（fr 版给的 es 录音比 es 版多 3.6 倍）；
  音标和释义**不能**取并集，要裁决。
- 🔴 **关系字段两级都要取**：kaikki 把 `derived` 同时放在词级和义项级，
  es 只取了词级 ⇒ **漏 20,193 条**，靠外锚闸才发现。
- 🔴 **合成音选词按频次 `freq_zipf`，不是按 CEFR `level`** ——
  `level` 只给内容词打标、语法词全 NULL，结果 `es/me/hay/está` 六个最常用词
  一个合成音都没有，反而给了 zipf 1.01 的 `lavaparabrisas`。
- 音频**不进 SQLite**（写库前要全文件复制备份）；按 sha1 前两位分 256 个子目录。
- 🔴 **哈希契约 Python 和 TS 各写一遍，差一字节全库静默降级** —— 必须有断言。

## 七、闸（贯穿全程，不是最后一步）

### 7.1 三类闸，缺一不可

| 闸 | 锚在哪 | 命运 | 落地 |
|---|---|---|---|
| **写库闸门** | 列的非空计数 | 永不过期 | `dbtool.session(expect={})` |
| **外锚闸** | 外部 dump | 永不过期 | `verify_vs_dump.py`（重扫 dump 逐条 diff） |
| **回归闸** | 历史修复清单 | 永不过期 | `tests/test_no_regression.py` |
| ~~自比闸~~ | 自己的上一版 | **必然过期** | 只能验"搬运忠不忠实"，不能验"数据对不对" |

### 7.2 每张出版层表至少一道锚在 dump 上的闸

**它不认识我们的表结构，所以我们改结构它也不失效。**
三条设计要点：
- 只允许两种归一（剥定界符、压空白），**绝不调用自己的转换器**；
- **闸自证**：库里出现的每一种取值必须在闸的扫描表值域里，否则报「闸失效」
  （`derived` 漏收就是这么发现的）；
- 「词形不在库里」单独报、不计入失败 —— 那是收词缺口，混在一起报闸就永远非零。

### 7.3 闸写完必须变异验证

**一条永远通过的检查等于没检查。** 三条要求见 `PITFALLS` G3。

### 7.4 回归闸挂进写库闸门

让「重建抹掉旧修复」在**产生它的那次写库**上报出来，而不是十天后偶然撞见。
每条断言带**已接受基线 + 理由**，否则闸永远红、一周内没人看。

## 八、验收与性能（数据补齐**之后**）

### 8.1 🔴 性能必须在数据长大之后再量

es 补完 `derived` 当天，`mano` 的关系从几条涨到 135 条，词条页从「看不出来」
变成 **6.3 秒**。**数据没补齐时这个问题量不出来。**

四个必查项见 `PITFALLS` F 组：COLLATE 不匹配、相关子查询入口、子查询要在 LIMIT 外面、
新索引对已预编译语句无效。判据只有一个：`EXPLAIN QUERY PLAN` 出现 `SCAN` 就是没走索引。

### 8.2 表拆多了不慢
`getEntry` 是**10 条小查询而非一条大 JOIN**（义项↔释义、义项↔标签都是 1:N，
一条 JOIN 会把两个 N 乘起来）。`mano`（26 义项/135 关系/29 例句）热态 **6.7 ms**。
**决定快慢的从来不是表的数量，是索引对不对得上。**

### 8.3 判官只在「确定性做不了」时用，且必须先跑负控

见 `PITFALLS` H1。同一批数据 v4-pro 抓住 100% 负控、豆包 13%。
**能确定性回源比对的，根本别问模型。**

## 九、产品化（半天）

数据做完 ≠ 能对外用。es 上补的：

- 统一 JSON 错误出口（原来 `?limit=abc` 回 HTTP 500 + **完整调用栈和服务器绝对路径**）；
- 入参校验（`Math.max(NaN,1)` **还是 NaN**，钳位对 NaN 完全无效）；
- LIKE 通配符要在**应用层**挡，**不能加 SQL 的 `ESCAPE`** —— 实测加了就从
  索引搜索退化成全表扫 114 万行。判据：库里一个词头都不含 `%` `_` `\`；
- `/api/v1` 版本前缀，旧路径留作兼容；
- **启动探活**：真开一次库跑一条查询。`fs.existsSync` 只能说明文件在，
  说明不了库能用（传了一半 / 权限 / schema 不对，它全返回 true）；
- 健康检查要反映真实探活结果 —— `return {ok:true}` 是**永远为真**的健康检查；
- 🔴 **数据目录必须能用环境变量指定**。默认值若从源码文件位置往上数几层推出来，
  打包之后必然指错，而症状是「语言列表空着」，一条报错都没有。

## 十一、三条压过一切的原则

1. **错比缺更伤权威。** 拿不准就不写，别猜。
2. **先问「是不是已经有人做好了」。** 跨版收割、真人录音、西语版的 `ks`
   —— 三次都是"我们没去拿"被当成了"没有数据"。
3. **可逆优先。** 发现自己在为一个不可逆方案设计一整套前置验收 / 分档 / 抽样流程时，
   **先回头看方案本身能不能变可逆** —— 比把流程做扎实便宜得多。
   （合并义项从「删行」改成「写字段」就全可逆了。）
