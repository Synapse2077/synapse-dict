### 🔴 与 it 的五处关键差异 —— 工期不能照抄 it

**① 收词面是 it 那轮的数倍。**
法文版有 **2,030,795 个法语词形**，我们库里只有 385,216 ⇒ 缺口 **约 165 万**。
it 那轮是 584,904 → 1,498,956（+156%）；fr 若全收会到 **约 200 万行**，
库估计 **1.3–1.6 GB**。阶段 3 是全计划最重的一段，**必须先定收到什么程度**（见 §五 待决策 1）。

**② 本语言原文释义面比 it 大 3 倍。**
it 是 714,223 条意语义项（阶段 1.5 的对象），fr 是 **2,106,669 条目带法语释义**。
⚠️ 但 it 那一阶段**实际模型调用 0 次** —— 意语版能确定性 1:1 对上，估的 3–4 天没花掉。
**fr 能不能同样对上是未知的，这是全计划最大的一个未知数。**
⇒ 阶段 1.5 排期必须写成「先做 1% 切片的可对齐性实测，再决定走确定性还是走模型」。

**③ 真人录音是 es/it 的 20 倍。**
法文版 244,777 条带录音，跨版并集还能再加（中文版 25,185 / 英文版 92,458 / 德文版 9,228）。
对比：**es 库现在只有 11,203 条、it 12,188 条**。
⇒ **阶段 6 的合成音很可能整个不用做**（it 的合成音你判定质量不够已删；es 的 19.6 万在用）。
先量真人录音落地覆盖率，够高就不做 TTS —— 省下 it 那轮的 0.5 天 + 跑批。

**④ 明确不造 G2P，这条七月就定了。**
`fr-DESIGN.md` §1：法语哑音末辅音 / 联诵 / 省音 / 一音多写，规则 G2P 性价比低。
对比 it：**73.4% 的音标是我们自己 G2P 算的**。
⇒ fr 的音标只能靠「kaikki 自带 + 从 lemma `forms` 收割 + 跨版并集」，
**覆盖上限受源头限制**，做不到 it 的 73.5%。阶段 4 更简单，但要**先把覆盖上限量出来**再定验收线。

**⑤ 中文版给了 15 万条人工中文，这是 es 那轮没有的。**
151,537 个法语词形带中文释义（`Japon → 日本`、`Monaco → 摩納哥（…）`），
其中 **132,773 我们库里已有、18,764 是新词**。
⚠️ 三个坑先记着：**繁简混杂**（蘇格蘭 / 摩納哥 / 蛋糕通稱）、**pos 大量是 `unknown`**、
**源头自带错**（`épee` 缺重音符、`Lyons` 应为 Lyon）。
⇒ 它**不是真值源**，是**第二意见**：用来裁决和补新词，不能直接覆盖。
（对照 `[[gloss-three-languages]]`：es 那轮 zh 版 27,475 条人工中文最后只用上 37 条。
fr 这次面大得多，值得单独排一步量它到底能用上多少。）
