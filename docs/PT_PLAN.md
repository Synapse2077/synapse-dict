### 1.3 🔴 参照系不是「一门语言」，是分维度选

> 用户 2026-08-29 问：「pt 和 fr 是近亲吗，为啥不同时参考 es 和 it？」
> **他是对的，本计划第一版把 fr 当成了唯一参照系。** 回源核对之后：

`pt/pipeline/build.py` 的文件头自己写着 **pt 独立管线，不 import 其他语种、不复用其他语种
schema**，而且两处明确写的是**与法语相反**：

```
· 明确不设 aux（葡语无 avoir/être 式逐动词助动词选择）
· 变位形 IPA 无法从 lemma forms 收割（葡语 forms 不带 ipa，与法语相反）
```

⇒ 它把 fr 当**对照组**写的，不是当模板。而「pt∩fr 列重合 81%」（实测，es 71% / de 65% /
it 42%）是**工程重合不是语言学亲缘** —— fr 与 pt 的 `build.py` 是同一周、同一套
「把本质字段升为一等字段」思路写出来的兄弟。拿它当近亲的证据＝把相关当成了因果。

**语言学上 pt 最近的亲戚是 es**（同属西伊比利亚语支），fr 是高卢-罗曼、it 是意大利-罗曼。

四门的 `dict` 列（实测）：

```
es (33)  reflexive conjugation stem_change pp transitivity feminine plural comparative
it (20)  aux conj transitivity pronominal gender plural plural_gender number_note
fr (31)  aux vgroup transitivity pronominal pp feminine invariable adj_pos government
pt (31)  vconj transitivity pronominal pp pp_short feminine plural adj_pos government
         ipa_br ipa_pt                                ← 四列没有任何其他语种有
```

| 维度 | 参照谁 | 依据 |
|---|---|---|
| **词法概念**（变位类/代词式/阴性形/过去分词）| **es** | 西伊比利亚语支。es `conjugation`+`stem_change` ↔ pt `vconj` 是同一件事；es `reflexive` ↔ pt `pronominal` 同一件事换个名。fr 的 `aux`/`vgroup` 是法语特有，pt **明确不设** |
| **G2P 造不造、怎么验收** | **it** | 六门里唯一趟过 G2P 的（73.4% 自己算），并留下标尺：规则裸路径 vs 人工源一致率 57.2%，有背书层 87% |
| **双读音落表结构** | **谁都不是** | `ipa_br`/`ipa_pt` 是 pt 独有 ⇒ 必须自己量（`[[es-v3-structure-backfill]]`）|
| **v3 表结构 / 三道闸 / 记账纪律** | **fr** | 最新最完整（16 表 + 契约 25 + 回归 28 + 账的闸）|
| **跨版收词的方法** | **fr** | 12 个源的探测流程最完整 |
| **判重合并** | **es（反面教材）** | es 186 条判重 12.4% 是义项错配 ⇒ PLAYBOOK 明令下一门不做自动判重 |

🔴 **本计划其余各节凡是写「同 fr」「照抄 fr」的，都要按本表复核一遍** ——
`FR_PLAN` 那轮的教训是「五处照搬 it 就会错，**全是量出来的**」，
以 fr 为唯一参照系是同一个错误换了个方向。

### 7.5 这一轮暴露的两个**机制**缺口（已做成闸，不是记在文档里）

1. 🔴 **闸打印的回滚命令指向一个已被删掉的文件。**
   实测：同一个脚本连着跑两版，第一版抛 `IntegrityError` 走异常路径**自删备份**（那次是对的，

   这是既定策略（用户 2026-08-25「该删就删，果断一点」），**不擅自改**，但后果需要你知道。
