# 意大利语分阶段计划

> 配套文档：结构照 `SCHEMA.md` v2（**不要重新设计**）、顺序照 `PLAYBOOK.md`、
> 动手前读 `PITFALLS.md`。本文件只解决一件 es 上始终缺失的事 ——
> **每个阶段"做到什么算完"，以及用什么判据证明它完了**。

## 零、为什么要有这份东西

es 花了约三周，其中**至少三分之一是返工**。返工不是因为做得不努力，而是因为
**es 从来没有「完成的定义」**：每天发现的缺陷都是真的，所以每个都值得做，于是永远做不完。

本计划对每个阶段规定三件事：

- **完成的定义** —— 一句可判定的话，满足了就是完了，不再"顺手多做一点"
- **验收判据** —— 用什么命令/数字证明它满足了，且这个判据必须**能失败**
- **明确不做** —— 这一阶段刻意不碰的东西，发现了也只记账

### 三条贯穿全程的规矩

1. **新发现默认进 backlog。** 只有「用户会看到错的内容」才允许打断当前阶段。
   `Guineo` 标成"形容词"是可打断的；某条定义有 247 个字不是。
2. **闸和数据同时做**，不是最后补。锚外部 dump 的闸永不过期，锚自己上一版的必然过期。
3. **闸写完必须变异验证** —— 故意改坏几条，闸必须报出来。一条永远通过的检查等于没检查。

## 阶段 -1 — 版本探测与取数（0.5–1 天）

**这一阶段在 es 上是花过学费的，别跳。**

维基词典按**版本**组织，每个版本是"某社区用该语言写的、讲多种语言的词典"。
所以「做意语就下意语版」是**错的直觉**，`probe_editions.py` 的文档里记着实测：

> **意语版 38 MB 只有 40,090 条意语音标，而法语版里的意语有 684,198 条（17 倍）。**

⇒ 手上那个 `data/dumps/itwiktionary.jsonl.gz`（38 MB）**不能当主源**。

### 四条必须守的规矩

1. **必须实测，不能猜。** 每个语言在各版本里的排名都不一样（社区活跃度不同）。
   `kaikki.org/<xx>wiktionary/` 索引页直接列出该版本覆盖的每个语种及义项数，免费、不下载。
2. **下切片，别下整包。** 非英文版也有 per-language 切片（rawdata 页说只有整包，那是不全的）。
   法语版五个目标语言切片合计 229 MB vs 整包 676 MB，**省 66%**；
   中文版整包下过 215 MB，其实西语切片 10.3 MB 就够。
3. **语种名是用该版本自己的语言写的**（Spanish / Español / Espagnol / Spaans / 西班牙語），
   靠名称模式识别；识别不到时脚本会列出该版本全部语种供人工确认，不假装万无一失。
4. **同一版本可能有多个本地名**（中文版的「西班牙語」和「西班牙语」是两个独立切片，都得取）。

### 版本的分工不是"谁更全"，而是按字段分

- **英文版 = 结构基准，不是内容上限**（六语种里只有 en 自己排第一）
- **词形、录音可以取并集**；**音标、释义、语法要裁决**，不能无脑合并
- **释义只保留三语**（中文 + 英文 + 意语）。de/fr/pt/es 版的释义**不收** ——
  实测每个维基版只给"自己语言的词"写定义，对外语词只写翻译

**完成的定义**
产出一张《it 版本取数表》：用了哪几个版本、每个版本取哪个切片、各贡献什么字段、
文件落在哪、各多大；并按此下载完毕。

**验收判据**
1. `python3 scripts/probe_editions.py --lang it` 的完整输出存档，
   排名前 5 的版本及其意语义项数逐个列出（**这是选择的依据，不是事后追认**）
2. 每个下载的切片：行数 + 意语条目数实测，与索引页声称的数字比对
3. 明确写下每个版本**负责哪些字段**，以及取并集还是要裁决

**明确不做**
不下整包（除非该版本确实没有切片）；不收 de/fr/pt/es 版的释义；
这一阶段不解析、不入库，只取数和记账。

es 把 8 万条对齐映射存成"definition 第几行"，而四个脚本会重排它 ——

只要还留着按行号引用的写法，它随时会再烂一次。

**完成的定义**
`dict` 已降到 21 列；十二张表全部建成且结构与 `SCHEMA.md` v2 逐列一致；
每条 definition 行都有一个 `sense.id`，全库不存在任何"第几行"式引用。

**验收判据**
1. 表结构与 `SCHEMA.md` v2 **逐表逐列**比对，差异为 0
2. **可逆性回核**：从新表重建原始 `definition` / `translation` 两列，
   与迁移前**逐字节双向**比对，100% 一致（非抽样 —— 这是"有没有错配"能否判定的关键）
3. 从 `dict` 搬走的每一列，在新表里逐行核对搬运无损
4. 全库 grep 确认没有残留的行号引用写法
5. 变异验证：打乱 3 条映射 + 改坏 2 条搬运结果，五条必须全被报出

**明确不做**
不改任何列的**值**（只搬不改）；不去修那 1 条行数不等的记录（留到阶段 1）；不碰展示层。

## 阶段 1.5 — 意语原文释义层 `sense_it` + 翻译（3–4 天）

🔴 **这是初版计划整个漏掉的一层，也是全项目最贵的一段**（`PLAYBOOK` 第五节：
「义项与释义，一周，最贵的一段」）。

`it.dict` 的 `definition` 全是**英文**（`fare` → "to do / to make"），来自英文版。
**意语版自己写的释义，库里一条都没有。** es 的对应物是 `sense_es`（173,422 条、100% 有中文）。

2026-08-12 实测 `itwiktionary.jsonl.gz`：

```
总行数         799,600
lang_code=it   560,357
带释义的词条   559,690
意语原文义项   714,223   ← it 库里为 0
```

⚠️ 714,223 是**上界**，混着 `plurale di X` 这类变形指针，要按 es 的做法过滤后才是真实工作量。

### 五条纪律（`PLAYBOOK` 5.1–5.6，每条都是踩出来的）

1. **结构三层，一次到位** —— 证据层 / 出版层 / 释义层，别先做两层回头再拆
2. ⭐ **翻译与对齐一次调用产出** —— 多吐 `en_i` 下标零成本。
   es 实测 46 tokens/词 + 50 tokens/义项
3. **模板在模型前面** —— 变形描述这类能确定性生成的，绝不送模型
4. **释义只保留三语** —— 中文 + 英文 + 意大利语。其余版本的释义不收
5. 🔴 **不做自动判重合并** —— es 上 186 条判重里 12.4% 是义项错配，已判定失败

### payload 四条纪律（5.5）

交叉引用要喂被引词的中文且限定条数／meta 标签要说明否则会被写进释义／
句末标点／wiktextract 残渣要清。

**完成的定义**
`sense_it` 建成并 100% 有中文；每条能锚回 `itwiktionary` 原文；
与英文版侧的义项完成对齐（同一义项的两个来源并成一条，不重复显示）。

**验收判据**
1. 条数 == 过滤后的期望值，**差一条查到底**
2. 逐条锚回 dump（外部闸，永不过期）
3. 对齐质量：抽样盲测（抽掉证据、对另一版真值），bad 率报出
4. **判官用前必跑负控** —— 负控不过就换判官，不是形式
5. 变异验证：改坏 5 条对齐关系，闸必须全报出

**明确不做**
不做判重合并；不为个别释义质量停下重译（记账）；不收 en/it 以外版本的释义。

### 🔴 同时处理 `SCHEMA` §9 第 1 条：被误判成变形层的词

⇒ 本阶段必须查一遍 it 有多少个，并把它们移回词条层。

**验收判据（补）**
5. `alt_of` 与 `form_of` 分开处理，抽 50 条人工核对
6. 移回词条层的词，界面上必须有释义（**查落点，不是查列**）

## 阶段 4 — 音标迁移：`ipa` 列 → `pronunciation` 表（1 天）

**这不只是核对。** it 现在的音标是 `dict` 上的**一个列**，而 v2 里音标是一张独立的表
（es 的 `pronunciation` 有 386,557 行）。拆表的起因是 `SCHEMA.md` §1.3 记的那条缺陷 ——
**一个列只能存一个值，音标的变体正在被丢掉**（半岛音/拉美音、宽式/严式、多重读法）。

it 的 `ipa` 99.9% 覆盖、且有 `ipa_src` 来源列，所以**内容不用重做**，
要做的是把一列展开成多行，并在展开过程中把源头本来就有、却被列结构挤掉的变体找回来。

**完成的定义**
`pronunciation` 表建成；每条音标带 `notation`（宽式/严式）与来源；
`dict.ipa` 单列里丢失的变体已从 dump 找回并落表。

**验收判据**
1. **回源计数**：直接扫 dump 数出意语条目应有的音标条数，与落表条数比对，
   缺口按**条**报出上界（不是按词形 —— es 就是漏了这层，`derived` 少收 20,193 条）
2. 可逆性回核：从 `pronunciation` 表能重建出原 `dict.ipa` 列，逐字节一致
3. `ipa_src` 为空的行数为 0（证明不了来源就写 `unknown`，**不猜**）
4. normalize 往返：`normalize(normalize(x)) == normalize(x)`，全量
5. 存裸、展示层加 `/.../`（六语种统一约定）
6. 变异验证：删 3 条音标 + 改 2 条 notation，闸必须全报出

**明确不做**
- **不用 G2P 重算**（es 上 `eigenvector → eixembeɡˈtoɾ`）
- 判据只能是"回权威源查不到 **且** 违反音系"，不能是"看着不像意语"
- 变形层不是风险面，别去大改（es 实测变形层标出率比 kaikki 原生还低）

## 阶段 6 — 发音合成（0.5 天 + 跑批）

**完成的定义**
主力音全量生成，哈希契约两端一致，文件零缺失零字节。

**验收判据**
1. **哈希契约 Python 与 TS 各写一遍并逐条比对**（差一个字节全库静默降级）
2. 抽 100 个含重音符/特殊字符的词，两端哈希 100% 一致
3. 生成文件数 == 期望数，零字节文件为 0，HTTP 200 且 MIME 正确
4. 挑词判据用 `freq_zipf`，**不要用 `level`**（es 上 `level` 给语法词全 NULL，
   导致 `essere`/`avere` 这类最常用词一个音都没有）

### 真人录音：这是一个**决策**，不是默认丢弃

录音 URL 在语言版 dump 里是**白送的**（`mp3_url` 直接带），de 覆盖 76%、fr lemma 67.7%。
贵的只是下载：`upload.wikimedia.org` 是读者 CDN、**有意限流**，es 实测 8 并发只到
0.6 条/秒、220 次重试、25 条 429，全量约 6–9 小时（落盘仅 276 MB）。

⇒ **先把 URL 收进 `audio` 表**（几乎零成本），下不下载单独决策。
⚠️ 跨版收割必须**按语言码过滤**，es 曾因按词形匹配混进 63 条非西语录音。

**明确不做**
不在本阶段下载录音文件（URL 先入库）；不做 TTS 替代真人录音的质量评比。

## 阶段 9 — 产品化（0.5 天）

`PLAYBOOK` 第九节。**数据做完 ≠ 能对外用**，以下每条都是 es 上补过的：

- **统一 JSON 错误出口** —— 原来 `?limit=abc` 回 HTTP 500 + 完整调用栈和服务器绝对路径
- **入参校验** —— `Math.max(NaN, 1)` **还是 NaN**，钳位对 NaN 完全无效
- 🔴 **LIKE 通配符要在应用层挡，不能加 SQL 的 `ESCAPE`** ——
  实测加了就从索引搜索退化成**全表扫**。判据：库里一个词头都不含 `%` `_` `\`
- **`/api/v1` 版本前缀**，旧路径留作兼容
- **启动探活：真开一次库跑一条查询** —— `fs.existsSync` 只能说明文件在，
  说明不了库能用（传了一半 / 权限 / schema 不对，它全返回 true）
- **健康检查要反映真实探活结果** —— `return {ok:true}` 是永远为真的健康检查
- 🔴 **数据目录必须能用环境变量指定**。默认值若从源码位置往上数几层推出来，
  打包后必然指错，症状是「语言列表空着」，**一条报错都没有**

**完成的定义**
以上七条全部就位，it 在 `/api/langs` 中可见并可查。

**验收判据**
1. `?limit=abc`、`?limit=NaN`、`?q=%`、`?q=_` 逐个实测，均返回结构化 JSON 错误
2. 词头含通配符的行数为 0
3. 把 `SYNAPSE_DATA_DIR` 指向不存在的路径 → 启动必须**报错退出**，不能静默起来
4. 故意传一个截断的库文件 → 探活必须失败

**明确不做**
不做鉴权、限流以外的运维功能。

## 阶段 X — 贯穿全程的两件事

### `FRAMEWORK` 五之二：写 it 的「约定宪法」

每个语种要有一份自己的约定记录：音标记法取哪一种、性别冲突信谁、
变形层边界划在哪、释义收哪几语。es 的教训是这些约定**散在对话里**，
回头没人说得清当初为什么那么定。**边做边写，不要最后补。**

### `SCHEMA` §9 第 3 条：`level` 是全库唯一没有源、也无法回源的字段

es 核心层 A1/A2/B1 里 **42.4%** 是专名/词缀/缩写/纯符号（`« »` 被判成 A1）。
结论是**不要试图修 `level`**，而是加客观频次列 `freq_zipf`（wordfreq，离线、
同输入永远同输出），`level` 一个字节不动 —— 加列是加法操作，不用就不查。

🔴 wordfreq 三个陷阱：多词的 zipf 是**拼**出来的／**词缀被静默剥掉再查**
（`a-` 拿到介词 `a` 的 7.36）／大小写折叠。
判据只能是 `tokenize(w) == [w.lower()]`，**不能数 token 个数**。
